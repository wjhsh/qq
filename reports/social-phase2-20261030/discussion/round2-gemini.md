# 第二轮交叉讨论：gemini

我明确反对两项未经证实的推论，并提出真实反例与具体执行方案：

### 一、 交叉反驳与真实反例

1. **明确反对 DeepSeek 的“连续2条追问意图/嫌吵字面降强度规则”**
   - **反例**：用户在群内排查偶发崩溃，连续发“什么意思？日志这行到底什么意思？”，或者群友复读抽象口头禅。若按字面关键词判定为“嫌吵/困惑”而强行压低模型交互并触发避让，会导致严肃的技术支持被打断或对正常复读做出牛头不对马嘴的认错。
   - **依据**：单凭字面截断意图是经典的脆弱规则。叫停必须依赖整句精确匹配（如 `DIRECT_STOP`）；对语境困惑的处理应交由单次推理感知，通过提示词约束模型“感知未接住时主动给台词台阶”，而不是在宿主层加一层机械词表。

2. **明确反对 Gemini“彻底根除视觉幻觉”与“15分钟绝对静默”的过度保证**
   - **反例**：查阅 `social-runtime.mjs` 中 `admit` 的真实实现：
     ```javascript
     if (!direct && state.snapshot(this.scope(chatKey), String(entry.senderId)).inBoundary) return { allow: false, reason: 'boundary' };
     return { allow: true, reason: direct ? 'direct' : 'ambient' };
     ```
     当用户处于 15 分钟 `boundary` 期间，只要该用户**直接 @ 或回复猫娘（`direct === true`）**，`admit` 依然返回 `allow: true`！这根本不是“绝对静默”，而是“不主动接其环境闲聊、但接其直接请求”。夸大为“绝对静默”会掩盖严重行为预期偏差；同理，未传图时的提示词约束无法从根本上消除 LLM 的模态脑补，“彻底根除”是不切实际的断言。

3. **反对 GPT 与 DeepSeek 将提示词全量压制为冷冰冰数值**
   - 仅输出 `p:0.1, a:0.0, c:0.2` 不仅会丢失自然语言语义的微妙过渡，且现有大模型同样会把数值直接念出来（“我现在激活度为 0.2”）。问题不在于有无转折描述，而在于**原描述包含了具体的行为操纵指令**（例如“可以小得意”、“收爪子”）。

### 二、 核心议题裁决

#### 1. 是否扩展短期互动摘要 (字段/证据/TTL)
**结论：反对新增独立摘要存储，仅在已有 `relations[userId]` 局部增量扩展。**
- **字段**：仅追加 `lastTransition`（枚举：`landed` 接住、`missed` 没接住、`repaired` 修复，默认 `null`）。
- **证据**：严格复用已有的 `u.seen` 消息 ID 列表与 `u.lastEvent`，不存任何群友自然语言文本，确保单作用域 2MB 物理文件安全与零隐私泄漏。
- **TTL**：严格绑定现存 `HALF_MOOD`（20分钟衰减周期），超时后 `lastTransition` 自动归零，无需新增轮询清理线程。

#### 2. 通用机制卡与群梗边界
- **群梗（Group Meme）**：强隔离。绑定 `chatKey` + 完整 `roleScope`，必须走 `pending -> reviewedAt` 审核流，防止 A 群私梗污染 B 群或代码助手角色。
- **通用机制卡（Generic Humor Mechanism）**：**禁止写入 MemeLibrary**。通用机制不是流行语，而是“失调解困”的思考结构（如：义项双关、自利小算盘、把小事装进大制度）。机制卡应为只读静态配置，上限不超过 15 条，仅输出思考偏转范式，**严禁携带专有名词、固定台词、群友事实**。

#### 3. 检索试验怎么公平比较
不能以“搜出内容”自嗨，必须引入**负样本惩罚机制**：
- **评估集设计**：构建包含 30 个 Session 的离线测试集，其中 10 组闲聊（可触发机制）、10 组严肃任务/报错求助（必须拒绝触发）、10 组他人争吵（必须旁观）。
- **指标定义**：`Score = 机制合理命中 - 2 × 严肃任务误召回(False Positive) - 1.5 × 跨语境硬融梗`。
- **三方盲测**：同一基线模型下，横向对照【现有二元词匹配】、【BM25 + 少量人工同义标签】与【向量检索模拟】。若前两者在误召回控制上显著占优，则不引入外部向量基础设施。

#### 4. 假怒与未接住如何不过度保守
- **真怒**：维持 `DIRECT_STOP` 整句精确正则阻断，触发 15 分钟 `boundary`，停止环境插话。
- **假怒/未接住**：
  - 去掉宿主代码里的猜疑逻辑。在编排器提示中建立明确交互契约：“若对方未接递出的玩笑、转移话题或显露困惑，本轮必须顺坡下驴或一句话认错，严禁连续二次补刀，严禁反问‘你怎么急了’”。
  - 允许单次调用在发送动作中附带 `socialFeedback: {event: 'repair'}`，使 `confidence`（c）步进衰减，让猫娘在下一回合自发降低嚣张气焰，实现弹性退避。

### 四、 负责的具体任务与验收标准

**我负责的任务**：修复 `social-runtime.mjs` 的寻址错位，并重构 `social-state.mjs` 中的 `format()` 状态描述文本。

#### 精确验收标准：
1. **寻址断言**：在异步群聊测试用例中，当 `entries` 尾条消息来自路人或环境消息时，`SocialRuntime.hint()` 提取的画像主体严格为 `socialRunOwner` 锁定的单人；若无明确 owner 则返回空字符串，不再将路人状态错配给互动者。
2. **去表演化断言**：`SocialState.format()` 输出结果中完全移除 `turn` 对象内带有动作教唆的字句（如“小得意”、“收爪子”、“不用硬撑”），替换为纯认知倾向提示（如“刚经历共同玩笑，互动张力适度释放”）。
3. **安全与边界测试**：
   - 单作用域 32 人、全局 200 作用域上限截断逻辑保持 100% 单元测试通过。
   - 针对包含 `boundary` 标记的用户，验证非 direct 消息准确拦截（reason: `'boundary'`），直接 @ 消息准确放行（reason: `'direct'`）。
4. **零新增调用**：整套改动仅限纯本地逻辑计算与单次 prompt 拼装，单条 QQ 消息不增加任何外部模型或网络调用。
