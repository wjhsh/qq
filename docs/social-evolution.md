# 哈基米社交行为系统：开发版

本轮在独立分支开发，没有上传程序到服务器、修改线上配置或覆盖角色卡。保留猫娘、小鱼干、罐头、尾巴、猫爪、傲娇、撒娇和嘴欠；新状态只调节互动倾向，不替换身份。

## 一个协调的运行路径

```text
现有 OneBot → ChatStore：保留原始正文、真实@对象、可信机器人标记
  → 现有触发/权限/输入过滤
  → SocialRuntime：不抢别人的@，明确叫停，已确认AI的有限互动
  → 现有编排器：当前角色 + 记忆 + 少量社交状态 + 最多2条已审梗机制
  → 原模型一次决定如何接：文字 / 表情 / 拍一下 / 工具 / 不回复
  → 原发送队列与真实回执：成功才记发送，完整回应可直接结束
  → 可选socialFeedback：引用本次真实输入，更新自己的短期情绪和缓慢关系
```

没有每条消息再跑一个分类模型；`socialFeedback`附在原来的发送或finish参数里。宿主验证引用确在本次对方实际正文、对象与角色版本正确、非已确认AI、每轮最多一次；它只能验证证据边界，**不能证明模型对情绪的解释一定正确**。

## 模块与复用

|模块|职责|复用/约束|
|---|---|---|
|`social-state.mjs`|连续愉悦/活跃/把握程度，缓慢熟悉度与亲近倾向；由事件改变并衰减|Gemini实现草案经主协调者修改；JSON原子保存，默认最多200作用域/每域32人，持久文件限制约2MB，90天不活跃回收|
|`social-runtime.mjs`|把结构证据、边界和状态接到现有编排器|延迟加载，坏文件保留并关闭本功能；群/私聊、完整角色版本及对象隔离|
|原`bot-interaction.mjs`|可信配置/传输标记识别自动账号|不从口吻猜机器人；默认仍不互聊，选开后仅群内真实@允许有限接话|
|原`tools.js`与发送队列|可选反馈、单次拍一拍、实际媒体回执收尾|不跟风拍未直接互动的第三人，除非收到带真实目标的明确请求；不赋予管理权限|
|原梗库/B站读取/抽取|自动候选待审核、来源与短上下文、完整角色版本匹配|DeepSeek实现草案经独立核查修正；不新建向量库或爬虫，不导入90条研究台词|

此前生产中已使用、尚未在原仓库提交的两处修复（自然表达与正文/桥接标签分离）纳入本分支，避免以旧发布文本作为开发起点而倒退。原检出目录里的其他未提交改动未纳入。

## 情绪与关系的含义

事件包含被接纳、共同玩一回、被安慰、修复误会、被纠正、被叫停及宿主成功事件。状态是猫自身的扮演倾向，不是给群友判定真实情绪。开心可以更活跃，受到安慰可以松口，被纠正先降一点把握程度；纠错和叫停不会永久扣关系。修复自己的错误也不自动表示对方同意继续逗弄。

情绪约20分钟半衰期，关系约7天向中性缓慢回落。正向事件每人每小时最多4次且至少间隔5分钟，防止密集发言刷亲密；日常消息数量本身不增加好感。关系是分群、分角色的窄状态，不是跨群的用户评分。共同经历仍使用已有记忆工具，暂时玩笑不会自动写成事实。没有新增自动整理长期经历的后台任务。

评价理论强调事件如何被解释，而情感动力学研究关注基线与回归强度，适合启发“事件→有惯性的状态”这一工程设计：[Scherer 2001](https://doi.org/10.1093/oso/9780195130072.003.0005)、[Kuppens等2010](https://doi.org/10.1037/a0020962)。这里的事件映射、数值、半衰期和预算是可调整的工程假设，不是论文证明的猫娘人格算法，也不把把握程度冒充标准PAD第三维。

## 停止、表情与其他AI

对原始正文、明确向自己的少数叫停句做确定性处理，不把“不要停”或引用里的“别说了”误当停聊。更含蓄的不适依赖模型理解与可选反馈，尚未保证识别。叫停可以取消同一发言者自己的当前互动和旧发送，不允许普通群友借此取消别人的任务。短期边界阻止再次随便搭话；之后此人明确提出认真问题仍可正常帮助。

只发一个表情也能构成完整回复。`send_sticker`、`send_face`和语音可传`finishAfterSend`，宿主确认实际消息ID后才结束；失败不伪造成功。图片占位与描述不等于看到了真实图片，这由提示和回放反例约束，不能声称靠程序完全消除了视觉幻觉。

已确认AI的可选互动只限群内直接@，实际发出后全群同角色5分钟冷却；历史仍不把机器人复读积累成群友风格。冷却当前为进程内状态，重启会清空；已有发送限频仍在。不开放直接@/引用机器人目标或私聊机器人等更广泛发送权限。

## 梗库迁移与审核

自动学习和手工采集都保存`pending`，主人明确`/梗库 收藏 编号`后才启用。旧的自动approved但没有reviewedAt的条目隔离；旧版本素材可在管理列表查看，明确收藏时绑定当前完整角色版本。不会自动批量批准旧数据。

来源区分标题、简介、人工/AI字幕与评论，保留评论/父楼定位，不存作者账号。字幕窗口使用重叠片段和前后短上下文，避免固定100字符切断转折；没有时间戳就标未知。评论失败时可仅形成字幕级候选，不冒充完整互动。现有日预算、冷却与权限/角色变化检查继续生效。

## Gemini语音的当前边界

[Google官方TTS说明](https://ai.google.dev/gemini-api/docs/speech-generation)提供专用语音接口。本实现按其REST Interactions格式发送原文及独立语气元数据，支持`gemini-3.8-flash-tts`、`gemini-3.8-flash-lite-tts`；默认Kore音色。没有增加真人声音复刻流程。

10月30日读取的现有Antigravity目录没有TTS条目；已检查的voice配置及探测进程环境没有可用语音密钥，**没有完成真实Google音频生成或QQ实播**。目录缺项不证明该代理永远不能支持，但不能假定订阅文本授权可直接调用官方TTS。

Gemini后端默认关闭，需管理员另行准备可用Gemini API凭证，由服务私有环境变量`GEMINI_TTS_API_KEY`读取。请求只发到固定Google HTTPS地址，禁止重定向；可沿用`QQ_AGENT_SPEECH_PROXY`或`HTTPS_PROXY`，不改变全局路由。默认需当前发言者明确要求语音；单次300字、单并发、同群60秒间隔、进程内每日最多20次尝试、45秒超时，失败也记尝试且不自动重试。

音频限制2MB、只接受单一WAV块，内存中转为OneBot record，不写音频文件。发送前检查`can_send_record`，成功还需实际回执。真实Google授权、服务器网络、QQ客户端音频转换仍需部署批准后的端到端验证，不能用模拟通过替代。

## 部署与回滚建议（尚未执行）

先完成盲评与失败例讨论，再批准单群试运行。部署前备份当前程序、配置及梗库/社交状态，确认已有171项基础检查和新检查通过。不要覆盖角色卡或现有私有数据目录。

最小试验配置见[非生产示例](../examples/social-development.json)：先开社交状态，AI有限互动保持关闭；先观察对象、任务、纠错和停止，再决定放开互损强度。运行期启停后刷新工具定义或重启，避免模型仍持旧参数。

回滚先将`socialBehavior.enabled`关闭并刷新/重启，保留状态文件供诊断；需要撤回程序时恢复批准前的源码版本。梗库新增可选字段仍用version:1，旧程序能读，但旧程序会恢复自动approved行为，因此应同时关闭autoLearn；是否恢复旧库须由管理员结合新候选确认。语音切回`voice.provider: edge`并重载插件即可沿用原路径。

不建议据目前的小样本对照直接全群开启。尚需更完整的多轮情绪场景、真实音画与人工盲评，及对冷却重启、关系遗忘和状态可视化的后续完善。
