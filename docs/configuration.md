# 配置与部署说明

QQ Agent 用 `QQ_AGENT_DATA_DIR` 指定私有数据目录，默认配置字段及合并规则以 `qq-agent/src/config.js` 为准。示例见 `qq-agent/config.example.json`；必须按自己的环境配置合法账号、白名单与模型渠道，示例值不能直接用于生产。

账号授权、API Key、QQ 接线令牌、控制台令牌分别保存在部署环境中。harness 使用本机令牌验证调用，图片任务读取独立保存的 Chat 授权；这些文件不属于源码仓库。不要提交实际 `config.json`、环境变量文件或授权文件。

入库版本已将旧源码里的 Google OAuth 客户端常量改为读取 `QQ_GOOGLE_OAUTH_CLIENT_ID`、`QQ_GOOGLE_OAUTH_CLIENT_SECRET`。需要刷新 Google 额度查询令牌时，应由部署环境提供这两个值；未提供时返回配置缺失，不提交空参数的刷新请求。示例见 `.env.example`。这项发布脱敏没有修改现有服务器文件，日后部署仓库版本前须先配置。

已有生产部署把源码放在 `/opt/codex-qq/`，数据放在 `/var/lib/qq-agent` 和 `/var/lib/qq-harness`。仓库布局与这些路径的对应关系是 `qq-agent/` → `QQ-agent/`、`harness/` → `harness/`，配套服务见 `ops/`。现有代码还有部署路径约定，迁移前须逐项核对；本版本没有声称可在任意目录直接重建整机。

更新流程：检查源码版本和服务空闲状态 → 备份待改文件 → 运行离线回归 → 分阶段验证 → 应用已审差异 → 检查 QQ、模型任务与发送回执。只更新 Chat 图片工作进程时，下一项图片任务会读取新源码；无需为此重启 QQ 客户端。

生产配置、账号和记忆另做独立的加密备份。Git 记录源码与脱敏报告，不能替代凭证恢复或数据备份。

## 首选模型自动恢复（2026-10-20）

`api.preferredRecovery.enabled` 开启后，QQ Agent 在现有进程内后台探测首选模型，无需另起服务。2026-10-20 15:04 的生产策略：首选 `gemini-3.8-flash-high`（high 思考），备用 `gemini-3.5-flash-lite`。3.8 尚未恢复时，活动配置保持 3.5 Flash Lite。管理员已要求取消 3 Flash 兜底，主配置与自动恢复配置均已移除该选择。

备用期间每 120 秒最多进行一次合成工具调用探测，10 秒超时，不附带群聊、私人记忆或 QQ 发送工具。必须由目标模型返回有效的 `health_ready(ok=true)`，连续成功两次才持久化切回；模型列表可访问、额度查询成功和普通 HTTP 200 都不能代替这一检查。恢复后停止后台探测，实际聊天遇到可降级的可用性故障时回退到 3.5 Flash Lite，冷却 300 秒后重新探测。内容安全、验证及明确客户端错误不会触发绕行。

关闭 `api.preferredRecovery.enabled` 可停用自动恢复。手动切到其他模型会暂停该策略；部署写入的 `endpointKey` 是端点与凭证的单向摘要，端点或凭证更换后需重新确认绑定，不自动在新渠道探测。探测会产生少量模型调用，不属于免费 `/models` 查询；事件仅在服务日志记录模型名、结果和恢复状态，不记录提示词、凭证或端点地址。模型切换只改 API 配置，不清空对话或记忆。

回归入口 `python tools/check.py` 已包含并发探测、连续成功门槛、失败冷却、取消、手动配置变化、真实返回校验及原有聊天/图像检查。

## QQ 调用 GPT 诊断

主人私聊发送 `/GPT 检查最近回复慢的原因`，或在允许管理的群真实 @机器人 后发送同一指令。诊断固定使用现有 Harness 的 `engine=codex, mode=diagnostics`，模型为 GPT-6.1-Sol、high，复用服务器保存的 Codex 授权并计入对应账号 Codex 额度。普通聊天模型不因此切换；`/任务` 仍默认使用 Pi。

`/GPT 状态`、`/GPT 列表`、`/GPT 结果 编号`、`/GPT 取消 编号` 支持查询与取消，`/诊断` 为同义入口。只提交本次原始问题和脱敏运行快照，不自动带入群聊、角色卡或私人记忆。任务只读分析生产状态，不能直接部署修改。群内仅发送通用确认，编号、诊断结果及完成摘要均私聊主人；群权限或主人权限撤销时停止回执。

任务按需启动，共用已有单任务队列与资源上限，不增加常驻模型进程。每10秒仅向本机 Harness 查询任务状态，不轮询上游模型；提交响应不确定时不自动重试。2026-10-20 观察期已关闭 `api.preferredRecovery.enabled`，第二个 Google 账号最初保持停用，后续手动启用见下一节；上文自动恢复行为仅在明确启用时适用。

## Google 双账号手动选择（2026-10-20 后续更新）

主人后续已授权启用第二账号。两个账号复用原网关8317和代理：账号1保持裸模型ID，账号2在授权文件使用 `prefix: account2`，网关设置 `routing.force-model-prefix: true`。账号2只注册 `account2/模型ID`，不会被裸模型请求选中；前缀在发送给Google前移除，正常凭证刷新会保留该字段。禁止把第二账号直接无前缀加入自动轮换池。

QQ 使用 `/账号 列表`、`/账号 当前`、`/账号 切换 1`或`2`；切换保留当前基础模型，目标账号未列出该模型时拒绝，不自动换其它模型。`/模型 列表`按账号展示，完整ID、编号或账号专属别名可选择具体模型，例如 `/模型 切换 账号2 Flash`。切换对全部QQ聊天生效，保留角色和记忆。独立Pi任务的配置保持独立。

裁判和梗素材提取的Lite模型跟随当前账号；额度查询也按选中账号分别缓存，缺失或重复匹配时不改查其他账号。两个账号共享原有请求保护：单并发、最小间隔、队列上限与失败冷却均保留；关闭自动恢复、自动备用及自动重试。手动切换不会绕过冷却。

授权文件与网关配置仍在服务器私有目录中，不进入仓库。发布版 `cloud_controls.py` 使用部署环境的OAuth客户端设置；此次既有服务器只合并账号选择和额度查询方法，保留原部署授权设置，不将其带回发布源码。
